# Best practices

How to write clear, correct and essential concepts.

## 1. Write the description first

It is the one sentence the agent sees on every turn. Test it: can a reader use the concept correctly from this sentence alone?

- Weak: *Invoices are generated by the billing system and represent the amounts customers pay.*
- Strong: *A bill for one billing period that cannot change after it is finalized.*

The weak one describes the system. The strong one defines the thing and carries the rule.

## 2. Say what it is not

Most mistakes come from two things the model blurs together. One Not sentence fixes that for good.

- *Not a [receipt](receipt.md): a receipt records a payment, an invoice requests one.*

## 3. A connection is a claim the reader needs

Everything else is a link in the body. "Invoice is related to Customer" says nothing. "Part of a workspace, never of a user" prevents a bug. A long list of connections means the concept is really two concepts.

## 4. Start with the type, then make the claim

- *Requires a [proration](proration.md) for any change after it is finalized.*
- *Part of a [draft invoice](draft-invoice.md) until finalization, then part of a [credit note](credit-note.md).*

"Requires proration" alone has the type but not the meaning.

## 5. A relationship with its own rules is a concept

Settlement is the relationship between a payment and an invoice. It has rules of its own, so it gets a file with two connections. This is also how three-way relationships work.

## 6. One word, one meaning

Use a concept's title every time. Declare other names once with "Also called", and never use them in prose. Two concepts called Account means one of them needs a new name.

## 7. Point to the source, never copy it

A concept links to the code or document that defines the thing. Copies drift. A source line stays true.

## 8. Start with ten to twenty

The terms used everywhere, the terms with two meanings, the terms nobody wrote down. Then stop. The base fills in from corrections, so it ends up holding exactly what caused trouble.

## 9. Keep these out

- Instructions: "always run the tests" goes in `AGENTS.md`.
- Procedures: "how to issue a refund" is a skill.
- Preferences and status: not meanings.
- Copies of docs: link them from a source line.

A concept says what a thing is. When a file starts saying what to do, it has stopped being a concept.
