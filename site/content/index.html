An open format for agent knowledge

Agents need skills.
They also need concepts.

A skill tells an agent how to do a task. A concept tells it what a thing means in your project, and how it connects to other things. A .concepts/ folder of plain markdown holds them.

One concept, one file

Two fields are required: a title and a one-sentence definition. A connection is a sentence whose first word is the type. The map lists every concept on one line, and the agent sees it on every turn.

See a whole base: this site's own sixteen concepts, rendered as the wiki.

Why concepts

A model knows what an invoice is. It cannot know what your invoice is, or that it must never change after it is finalized. No training run contains that. Concepts give it that knowledge, and keep it.

Shared understanding
People and agents use the same defined words. The agent stops guessing what your words mean, and conversations get shorter.
Evolves with the project
Grows from corrections, and changes in the same commit as the code. Never a stale wiki.
Progressive disclosure
The map is always in mind. Files load only when a task touches them.
Typed connections
Eight relationship types give the agent the shape of your domain, not a glossary. "Part of a workspace, never of a user" is what stops the wrong change.
Sources, not copies
Every concept points to the file or document that defines it, so it stays correct and stale ones are easy to find.
Reviewable like code
Plain markdown in git. A change of meaning shows up in the pull request, next to the code that caused it.
Checkable
Six validity rules: links resolve, every concept has a definition, the map matches the files. Run by the agent, or by npx concepts-sh check in CI.
Shareable
Push the repo and every concept has a URL. Others link to your concepts, pinned to a version, and write their own with yours as the source.
No lock-in
No tool, no server, no database. Works in any agent that reads AGENTS.md, and the files open in Obsidian or any markdown viewer.

Get started

  1. Install. npx concepts-sh init makes the folder, installs the skill, and adds one line to AGENTS.md. Or do those three things by hand.
  2. Ask your agent: set up concepts. It reads your schema, types and docs, writes the ten to twenty concepts that matter, and asks you about the rest.
  3. Correct it. When a term is wrong, say so. The agent fixes the file. npx concepts-sh check runs in CI, and npx concepts-sh wiki shows the base in a browser.

Eight relationship types

The first word of a connection is its type. The rest of the sentence is the claim.

TypeOpenerQuestion it answers
KindKind of X · Kinds: X, YWhat is it, more generally?
PartPart of X · Parts: X, YWhat contains it?
SameSame as XIs it the same thing under another name?
ReplacesReplaces X · Replaced by XWhat is outdated, and what replaced it?
NotNot XWhat is it confused with?
RequiresRequires X · Required by XWhat must be true first?
CausesCauses X · Caused by XWhat does it trigger?
UseUsed for X · Uses XWhat is it for?

Questions

Is this memory?
No. Memory is what one agent remembers privately. Concepts are shared meaning: in git, reviewed by the team, read by any agent.
Why files and not a database?
Files work in every agent, show up in pull requests, and need nothing running. The graph is built from the files whenever something needs it.
Can I share a base?
Push the repo. Others link to your concepts by URL, pinned to a version, and write their own concepts with yours as the source. Nothing is copied.
Do I need the CLI?
No. The format needs no tool. The CLI installs the skill, checks a base in CI, and builds the wiki.

Intelligence means having a sufficient number of clear, correct and essential concepts in your mind, and having established a sufficient number of clear, correct and essential connections among them.
